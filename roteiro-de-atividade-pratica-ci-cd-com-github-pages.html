CI/CD para iniciantes: criação e publicação de uma página HTML

Nome:
Turma:
Data:

1. Situação-problema

A empresa fictícia DevFlow Solutions atualiza com frequência a página de uma loja virtual. Para tornar a publicação mais organizada e reduzir tarefas manuais, a equipe deseja armazenar os arquivos do site em um repositório e automatizar sua publicação.

Nesta atividade, vocês criarão uma página simples em HTML usando o Visual Studio Code (VS Code), guardarão o arquivo em um repositório do GitHub, acompanharão um workflow do GitHub Actions e publicarão o site pelo GitHub Pages.

Adaptação para iniciantes: não será necessário instalar um servidor, configurar chaves SSH ou criar tokens de acesso. O GitHub Pages será usado para publicar a página.

2. Objetivos de aprendizagem

Ao final da atividade, espera-se que vocês consigam:

  • identificar, de forma básica, as etapas de um fluxo CI/CD;
  • criar uma pasta de projeto e um arquivo HTML no VS Code;
  • criar um repositório no GitHub e enviar arquivos para ele;
  • registrar alterações usando commits;
  • acompanhar a execução de um workflow no GitHub Actions;
  • publicar e conferir uma página usando o GitHub Pages;
  • explicar os benefícios, as dificuldades e os cuidados da automação.

3. Conceitos essenciais

  • HTML: linguagem usada para organizar o conteúdo de uma página web.
  • VS Code: editor de código usado para criar e editar arquivos.
  • Repositório: espaço on-line onde são guardados os arquivos e o histórico do projeto.
  • Commit: registro de uma alteração feita no projeto.
  • Push: envio das alterações para um repositório remoto, como o GitHub.
  • Workflow: conjunto de instruções executadas automaticamente pelo GitHub Actions.
  • CI — Integração Contínua: prática de executar verificações automatizadas quando o projeto muda.
  • CD — Entrega ou implantação contínua: prática de preparar ou publicar alterações de forma automatizada.
  • GitHub Pages: serviço do GitHub que publica sites estáticos, como páginas feitas com HTML e CSS.

4. Materiais necessários

  • computador com acesso à internet;
  • navegador de internet;
  • Visual Studio Code instalado, ou outro editor indicado pelo professor;
  • conta no GitHub;
  • arquivo de exemplo desta atividade;
  • apoio do professor para revisar as etapas.

5. Tarefa

Em grupo, criem uma página inicial simples para uma loja virtual fictícia. A página deverá conter:

  1. nome da loja;
  2. breve descrição da loja;
  3. pelo menos três produtos;
  4. preço de cada produto;
  5. uma forma de contato fictícia.

O arquivo principal deverá se chamar index.html. Ele será armazenado em um repositório do GitHub e publicado usando o GitHub Pages.

Privacidade: não incluam senhas, endereços, telefones, e-mails pessoais ou outras informações reais. Usem somente dados fictícios.

6. Procedimento

Etapa 1 — Criar a pasta do projeto no VS Code

  1. Crie no computador uma pasta para guardar os arquivos da atividade.
  2. Dê à pasta um nome simples, por exemplo, loja-virtual.
  3. Abra o VS Code.
  4. No menu do VS Code, escolha File > Open Folder (ou Arquivo > Abrir Pasta).
  5. Selecione a pasta loja-virtual que acabou de criar.
  6. No painel de arquivos do VS Code, crie um arquivo chamado exatamente index.html.
Atenção: confirme que o nome é index.html, com letras minúsculas. Evite nomes como Index.html, inicio.html ou index.html.txt.

Etapa 2 — Inserir o exemplo no arquivo

  1. Localize o exemplo de código apresentado mais adiante neste roteiro.
  2. Copie o código do exemplo, desde <!DOCTYPE html> até </html>.
  3. Cole o conteúdo no arquivo index.html aberto no VS Code.
  4. Salve o arquivo usando Ctrl + S (Windows/Linux) ou Command + S (macOS).
  5. Personalize o nome da loja, a descrição, os produtos, os preços e o contato fictício.
  6. Não apague as marcações HTML, como <h1>, <p> e <article>, sem compreender sua função.

Etapa 3 — Conferir a página no computador

  1. Salvem o arquivo index.html no VS Code.
  2. Localizem o arquivo na pasta do projeto usando o Explorador de Arquivos ou o Finder.
  3. Cliquem duas vezes no arquivo para abri-lo no navegador.
  4. Confiram se o nome da loja, a descrição, os três produtos, os preços e o contato estão corretos.
  5. Se fizerem alterações no VS Code, salvem o arquivo e atualizem a página no navegador.

Etapa 4 — Criar o repositório no GitHub

  1. Acessem o GitHub e entrem na conta.
  2. Escolham a opção para criar um novo repositório.
  3. Definam um nome simples, por exemplo, loja-virtual-ci-cd.
  4. Se o professor orientar, iniciem o repositório com um arquivo README.
  5. Escolham a visibilidade indicada pelo professor e criem o repositório.
  6. Deixem aberta a página do repositório para a próxima etapa.

Etapa 5 — Enviar o arquivo HTML para o GitHub

O objetivo desta etapa é guardar no repositório a página HTML criada no VS Code. O professor poderá orientar o envio pelo site do GitHub ou pelo controle de versão do VS Code.

  1. Na página do repositório, procurem a opção para adicionar ou enviar arquivos.
  2. Selecionem o arquivo index.html que está na pasta do projeto.
  3. Confiram se o arquivo aparece na lista antes de confirmar o envio.
  4. Escrevam uma mensagem clara para registrar a alteração, como Adiciona a página inicial da loja.
  5. Confirmem a gravação da alteração no repositório. Esse registro é um commit.
  6. Voltem à página principal do repositório e confirmem que o arquivo index.html está visível.
Se estiverem usando o VS Code: o professor poderá orientar a conexão do VS Code ao GitHub. Não compartilhem senhas nem tokens no código ou em mensagens. Se a conexão pedir autenticação, sigam somente as instruções oficiais apresentadas pelo GitHub e pelo professor.

Etapa 6 — Configurar a publicação pelo GitHub Pages

  1. No repositório, abram Settings.
  2. Procurem a seção Pages.
  3. Na área de configuração de build e publicação, escolham GitHub Actions como origem, se essa opção estiver disponível.
  4. Procurem uma sugestão de workflow para site estático. O nome pode ser semelhante a Static HTML ou Deploy static content to Pages.
  5. Peçam ao professor para revisar a opção selecionada antes de confirmar.
  6. Se o GitHub solicitar a criação ou confirmação de um arquivo de workflow, sigam a orientação do professor.
  7. Verifiquem se o workflow aparece na pasta .github/workflows/ do repositório.
O que é o workflow? É um arquivo de instruções que informa ao GitHub quais tarefas executar automaticamente. Nesta atividade, o workflow será usado para publicar o conteúdo do site. Se os nomes das opções estiverem diferentes, peçam ajuda ao professor.

Etapa 7 — Acompanhar a execução do workflow

  1. Façam uma alteração pequena no arquivo index.html, como corrigir uma frase ou mudar a descrição de um produto.
  2. Salvem o arquivo e enviem a nova versão ao repositório, registrando a alteração.
  3. Abriam a aba Actions do repositório.
  4. Localizem a execução iniciada depois da alteração.
  5. Aguardem a conclusão e observem o resultado indicado.
  6. Se houver uma falha, abram a execução para identificar qual etapa apresentou o erro e peçam orientação ao professor.
Como interpretar o resultado:
  • Em andamento: o workflow ainda está sendo executado.
  • Sucesso: as etapas terminaram sem indicar erro.
  • Falha: uma ou mais etapas encontraram um problema.

Etapa 8 — Conferir a página HTML publicada

Nesta etapa, vocês vão acessar no navegador a página HTML criada em index.html e verificar se ela foi publicada corretamente.

  1. Voltem à área Settings > Pages do repositório.
  2. Localizem o endereço do site disponibilizado pelo GitHub Pages.
  3. Cliquem no endereço ou copiem-no e abram em uma nova aba do navegador.
  4. Confiram se a página mostra o nome da loja, a descrição, os produtos e os preços.
  5. Comparem o conteúdo exibido no navegador com o arquivo index.html do repositório.
  6. Se o site ainda não estiver disponível, aguardem alguns minutos e verifiquem novamente a aba Actions.
Lista de conferência da página publicada:
  • o nome da loja aparece corretamente;
  • a descrição está visível;
  • há pelo menos três produtos;
  • cada produto tem um preço;
  • o contato é fictício;
  • não há dados pessoais reais;
  • a página publicada corresponde ao arquivo index.html.
